## [0.4.0] — 2026-08-12

### 추가

- **색이 안 칠해진 코드블록을 경고한다.** 몇 번째 블록인지까지 알려준다.

  > 색이 칠해지지 않은 코드블록이 2개 있습니다(2·3번째). 언어 태그가 없거나
  > Pygments가 모르는 이름입니다. 블로그 화면은 highlight.js가 언어를 자동 감지해
  > 태그 없이도 칠하므로, 그대로 두면 같은 글이 블로그에서는 색이 있고
  > Blogger에서는 무채색으로 나옵니다 — \`\`\`python 처럼 언어를 적어주세요.

### 왜

실사용에서 "코드블록 색이 제각각"이라는 보고가 나왔다. 조사해 보니 **변환기 버그가
아니었다.** 인라인 모드와 CSS 모드는 같은 코드에 대해 236자 전부 같은 색을 내고,
Pygments가 뱉는 클래스에는 빠짐없이 대응 규칙이 있다.

진짜 원인은 **양쪽 화면이 언어를 다르게 정한다**는 것이었다.

| | 언어 태그 있음 | 없음 |
|---|---|---|
| 블로그(highlight.js) | 그 언어로 칠함 | **자동 감지해서 칠함** |
| 이 변환기(Pygments) | 그 언어로 칠함 | **안 칠함** |

`highlight.min.js` 11.9.0의 `highlightElement` 본체에서 확인했다 —
`const r = t ? h(a,{language:t,…}) : E(a)`, 언어가 없으면 `E`(= `highlightAuto`)로
간다. 그래서 태그 없는 블록이 섞인 글은 블로그에서는 전부 색이 있고 Blogger에서는
일부만 색이 있다.

자동 추정(`guess_lexer`)으로 맞추는 길도 있었지만 **택하지 않았다.** Pygments의 추정은
highlight.js보다 부정확해 서너 줄짜리 조각을 엉뚱한 언어로 칠할 수 있고, 그러면 무채색
보다 나쁘다. 색을 지어내는 대신 **작성자에게 태그를 붙이라고 알린다.**

### 판단 기준은 언어 이름이 아니라 결과다

색이 안 붙는 경로가 셋이다 — 태그 없음 · Pygments가 모르는 이름 · `text`처럼
**알지만 칠할 토큰이 없는** 언어. 앞의 둘만 세면 `text`가 조용히 빠져나간다.
그래서 하이라이팅 결과에 `<span`이 있는지로 판정한다.

기존 '모르는 언어' 경고는 그대로 둔다 — 그쪽은 이름을 고치라는 더 구체적인 안내다.

### 테스트

43 → 48.

## [0.5.0] — 2026-08-15

**역방향 추가 — HTML을 마크다운으로 되돌린다.** 지금까지는 한 방향 통행이었다.

### 추가

- `converter/to_markdown.py` — HTML → 마크다운
- `app.py`에 `POST /api/to-markdown`, 화면 상단에 **방향 전환** 칩
- `cli.py --reverse`
- `tests/test_to_markdown.py` — 왕복·안정성·지저분한 입력·이스케이프 (테스트 50 → 96)
- 의존성 `beautifulsoup4` (사용자 승인). **`converter/__init__.py`에서 import하지
  않는다** — 블로그가 이 폴더를 복사해 쓰는데 그쪽은 정방향만 쓴다. 여기서 끌어오면
  블로그에 없는 의존성이 강제된다.

### 다루는 범위

| 입력 | 결과 |
|---|---|
| 우리 변환기 출력 | 실제 글(21KB)로 왕복 확인 — 렌더에 영향 없는 공백만 빼면 HTML 동일 |
| Blogger·워드프로세서 | div 수프·인라인 스타일·빈 `<span>`을 걷어낸다 |
| 임의의 웹페이지 | 조각 단위로 동작. **본문 추출은 하지 않는다** — 붙여넣을 부분은 사람이 고른다 |

되돌릴 수 없는 것(셀 병합 표·중첩 표·iframe)은 **원본 HTML을 그대로 남기고 경고한다.**
마크다운은 원시 HTML을 허용하므로 이게 정보를 안 잃는 유일한 길이다.

### 정방향 수정

- **코드블록에 `class="language-x"`를 되살렸다.** 이게 없으면 왕복에서 ```` ```python ````이
  그냥 ```` ``` ````으로 무너진다. 색은 이미 칠해져 있어 화면에는 영향이 없고,
  블로그 화면의 highlight.js도 같은 클래스를 읽으므로 되가져가도 그대로 동작한다.

### 실제 글에서 잡은 것

- **본문의 대괄호가 수식으로 둔갑하던 버그.** 처음에는 마크다운 기호를 전부
  이스케이프했는데, 본문의 `[이미지2 - 월별 단속]`이 `\[…\]`가 되면서 다시 변환할 때
  **arithmatex가 LaTeX display 수식 구분자로 읽어 문단 하나가 통째로 수식이 됐다.**
  → "그 자리에서 실제로 문법이 될 수 있을 때만" 이스케이프하도록 바꿨다.
  `2 * 3`은 건드리지 않고 `_밑줄_`만, 링크가 될 수 있는 대괄호만, 태그로 보이는
  꺾쇠만, 줄 맨 앞의 `#`·`>`·목록 기호만.
- **중첩 목록이 4칸이어야 한다는 것.** Python-Markdown 3.4.1은 CommonMark가 아니라
  원조 Markdown.pl 규칙을 따라 4칸부터 중첩으로 본다. 요즘 흔한 2칸으로 내보냈더니
  되돌린 글을 다시 변환할 때 중첩이 조용히 평평해졌다.
- **loose/tight 목록 구분.** 항목 사이 빈 줄 유무가 `<p>` 감싸기를 바꾼다.
  원본이 어느 쪽이었는지 보고 따라가지 않으면 왕복에서 항목 간격이 달라진다.

### 알게 된 것 (아직 고치지 않음)

**불릿 목록 바로 뒤에 번호 목록이 오면 두 번째 목록이 첫 번째에 흡수된다.**
`1. 2.`가 불릿으로 바뀐다. 반대 순서도 마찬가지다. 사이에 문단이 있으면 정상이다.
Python-Markdown 3.4.1의 동작이라 **블로그에도 같은 문제가 있다.**
`sane_lists` 확장이 고치지만, 넣으면 블로그와 출력이 갈라지므로 함께 결정해야 한다.

## [0.3.0] — 2026-08-12

Blogger 글 본문에 `<style>` 태그를 넣을 수 있다는 것을 확인하고, 이를 쓰는
출력 모드를 추가했다.

### 추가

- **출력 방식 선택** (`output` 옵션 / 화면의 `출력 방식` 칩 / `cli.py --output`)
  - `inline` — 모든 스타일을 `style=` 속성에 박는다 (기본, 기존 동작)
  - `css` — 맨 앞에 `<style>` 블록을 두고 본문은 클래스만 갖는다
- `converter/stylesheet.py` — 팔레트별 스코프 CSS 생성
- `highlight.style_defs()` — 문법 강조 색을 스타일시트로 빼는 경로
- 테스트 10개 추가 (총 43개)

### CSS 모드가 나은 점

- **조판이 더 정확하다.** 인라인으로는 표현할 수 없어 px로 어림잡던 blog.css의
  `> * + *`(형제 여백)와 `li + li`를 **그대로** 옮길 수 있다.
- **본문이 짧아진다.** 실측 손익분기는 원문 약 700자 — 그보다 길면 CSS가 유리하다.
  실제 글(원문 21KB): 43,637자 → 24,633자.
- 편집기에서 사람이 읽고 직접 손볼 수 있다.

### CSS 모드의 대가

- **RSS 피드에서 `<style>`이 제거된다.** 구독자에겐 서식 없이 보인다(읽히긴 한다).
- Compose(작성) 모드로 전환하면 깨질 수 있다. HTML 보기에서만 다뤄야 한다.
- AMP를 켜두면 못 쓴다 — AMP는 본문 `<style>`을 금지한다.
- **짧은 글에서는 오히려 길어진다** (스타일시트가 고정 비용이라).

### 안전장치

- 모든 규칙을 `.md2b.md2b-<팔레트>` 아래로 스코프했다. 글 목록·홈처럼 여러 글이
  한 페이지에 뜰 때 테마와 다른 글을 건드리지 않는다. 팔레트를 클래스에 넣어
  서로 다른 팔레트의 글이 같은 페이지에 있어도 충돌하지 않는다.
- 클래스를 겹쳐(`.md2b.md2b-dark`) 특이도를 올렸다. 테마 규칙에 지지 않는다.
- CSS도 개행 없이 한 줄로 낸다 — `<style>` 안에 `<br>`이 끼면 그 지점부터 깨진다.

### 수정

- **Pygments가 스코프 밖 규칙을 흘리던 문제.** `get_style_defs(scope)`는 넘긴
  선택자와 무관한 `pre { line-height: 125% }`와 줄번호 규칙 넷을 함께 뱉는다.
  앞의 것은 **테마의 모든 코드블록 행간을 건드린다.** 토큰 규칙만 남기도록 걸렀다.
- **다크 팔레트의 코드 배경이 라이트 값으로 덮이던 문제.** 같은 `get_style_defs`가
  끼워 넣는 `{scope} { background: … }`가 Pygments 스타일 클래스에 박제된 값
  (라이트 `#11162A`)이라, 뒤에 놓이면서 다크의 `#0A0F1A`를 덮었다. 함께 걸러냈다.
- **글자색을 컨테이너 상속에 맡기던 문제.** 상속은 요소를 직접 겨냥한 규칙에 무조건
  진다 — 테마에 `p { color: … }` 한 줄만 있어도 본문이 통째로 그 색이 됐다.
  적대적 테마를 흉내 내 확인했고, 글자를 담는 요소마다 색·글꼴을 명시하도록 고쳤다.

## [0.2.0] — 2026-08-12

Blogger 테마가 **검은 배경**일 때 본문이 배경에 묻히던 문제를 해결했다.

### 추가

- **팔레트 선택** (`palette` 옵션 / 화면의 `Blogger 테마 배경` 칩 / `cli.py --palette`)
  - `light` — 밝은 배경 테마용. blog.css 라이트 토큰 (기본값, 기존 동작)
  - `dark` — 검은 배경 테마용. blog.css `html[data-theme="dark"]` 토큰 그대로
  - `inherit` — 글자색을 **아예 지정하지 않아** Blogger 테마가 칠한다.
    어떤 테마에도 맞고 나중에 테마를 바꿔도 안 깨지지만, 블로그와 똑같은 색은 포기한다.
- 미리보기 배경이 선택한 팔레트를 따라간다 — 검은 테마에 얹은 모습을 그대로 보여준다.
- 테스트 7개 추가 (총 33개).

### 변경

- `theme.py`를 팔레트 구조로 재구성. 모듈 상수(`TAG_STYLES`·`WRAPPER`·`PRE_STYLE`)를
  `Palette` 데이터클래스와 `tag_styles(p)`·`wrapper(p)`·`pre_style(p)` 함수로 바꿨다.
  코드블록은 팔레트와 무관하게 늘 어둡다(블로그와 동일) — 배경만 팔레트를 따른다.

### 왜 이렇게 했나

인라인 스타일은 미디어쿼리를 담을 수 없어서 `prefers-color-scheme`으로 자동 대응이
불가능하다. 색을 박으면 한쪽 밝기에만 맞고, 안 박으면 블로그와 색이 달라진다.
양쪽 다 정답이 아니라 **선택지**라서 셋을 모두 제공하고 고르게 했다.

## [0.1.0] — 2026-08-12

첫 동작 버전. 마크다운을 Blogger 글쓰기 화면에 붙여넣을 수 있는 HTML로 바꾼다.

### 추가

- **변환 코어 `converter/`** — Flask/Django를 import하지 않는 순수 파이썬 패키지.
  - `pipeline.py` — 블로그와 같은 확장 조합(`extra`·`toc`·`fenced_code`·`pymdownx.arithmatex`)으로 마크다운 → HTML
  - `theme.py` — 블로그 `blog.css`(Slate & Navy)의 본문 조판을 인라인 스타일 표로 이식
  - `highlight.py` — 블로그가 쓰는 highlight.js `github-dark-dimmed` 팔레트를 Pygments 스타일로 옮겨 **서버에서 색을 인라인으로** 박음
  - `blogger.py` — 인라인화·개행 제거·이미지 절대경로·경고 수집
  - `snippet.py` — Blogger 테마에 넣을 KaTeX/Mermaid 스니펫 (단일 출처)
- **웹 UI `app.py` + `templates/` + `static/`** — 붙여넣기 → 자동 변환 → 복사.
  블로그 전용 페이지의 디자인 토큰·컴포넌트 이름(`b-btn`/`b-mono`/`ed-card`)을 그대로 따름.
  미리보기는 테마 스니펫을 넣은 iframe이라 **Blogger에서 보일 모습과 같다**.
- **CLI `cli.py`** — 파일 단위 변환. `--preview`로 브라우저 확인용 문서도 함께 저장.
- **테스트 `tests/test_convert.py`** — 26개 (stdlib unittest).
- **문서** — `README.md`, `docs/PLAN.md`, `docs/WORKLOG.md`, `docs/blogger-theme-snippet.md`.

### Blogger 대응 (이 프로젝트의 핵심)

- CSS 클래스가 무용지물 → 모든 스타일을 `style=` 속성으로 인라인화
- 개행이 `<br>`로 자동 변환됨 → 출력에 **개행 문자를 한 글자도 남기지 않음**
  (코드블록 줄바꿈은 `<br>`, 다이어그램 줄바꿈은 `&#10;`)
- `<pre>` 안 특수문자 → 이스케이프 유지한 채 Pygments 처리
- 상대경로 이미지 → 기준 URL로 절대화, 없으면 경고

### 수정

- **코드블록의 `"`가 `&quot;`로 새던 문제** — 되돌리는 대상에 `&lt;`·`&gt;`·`&amp;`만
  넣고 `&quot;`를 빠뜨려, 코드에 `&quot;`가 글자 그대로 찍혔다. `html.unescape`로 교체.
- **mermaid 다이어그램이 'Syntax error in text'로 깨지던 문제** — 개행 제거 과정에서
  다이어그램 소스가 한 줄로 뭉쳤다. `&#10;`(개행 실체 참조)으로 바꿔 Blogger의
  줄바꿈 변환은 피하면서 브라우저 DOM에서는 진짜 개행이 되게 했다.

### 알려진 제약

- `$$...$$`를 **문장 안에** 쓰면 arithmatex가 span을 이중으로 감싼다.
  블로그 파이프라인과 동일한 동작이라 그대로 뒀다. 블록 수식은 `$$`를 **줄 하나로** 띄워 쓴다.
- Blogger 테마 CSS가 `.article-body p { margin: 0 }` 같은 규칙을 강하게 걸어두면
  일부 여백이 덮일 수 있다. 인라인 스타일이 이기지만 `!important`는 못 이긴다.
